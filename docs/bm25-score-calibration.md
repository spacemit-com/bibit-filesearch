# BM25 得分标定（K 值）

> 适用：`retriever.py` 的 `self.bm25_half_score`（出厂默认 `2.8`）

## 一句话

`K` 是 **BM25 原始分的"半分点"**：原始分恰好等于 K 时，映射后的 `S_bm25 = 0.5`。

## 公式

```python
S_bm25 = raw / (raw + K)        # raw = BM25 原始分（无命中时为 0）
```

| raw | S_bm25 | 读法 |
|---|---|---|
| 0 | 0.00 | 没命中 |
| K/2 = 1.40 | 0.33 | 弱命中 |
| **K = 2.80** | **0.50** | 标定点 |
| 2K = 5.60 | 0.67 | 强命中 |
| ∞ | → 1.00 | 上界，永不到达 |

这是**绝对映射**：同一份文本在任何查询、任何结果集里都得到同一个 `S_bm25`。

## 为什么用绝对映射（不能用批内 min-max）

批内 min-max 把**本次命中集**里的最小分映成 0、最大分映成 1，尺度取决于同批数据：

- 两个原始分接近的文件会被拉成 0.0 与 1.0（分差 <0.01 也能变成整段极差），
  排名剧烈翻转；
- 未被 BM25 命中的文件被挤出窗口，结果集大小随输入批次漂移；
- 分数不再跨查询可比，无法作为融合分的稳定输入。

`raw / (raw + K)` 只依赖 `raw` 本身，无批次依赖，且跨查询可比。

## 重标步骤（语料 / 分块 / 分词变了就做）

```bash
# 前置：本地 embed 端点可用（默认 :18790）
# 1. 取语料（只读）
sqlite3 -readonly ~/.local/share/bibit-filesearch/filesearch.db \
  "SELECT file_id, text FROM chunks ORDER BY chunk_id"
```

```python
import sys
sys.path.insert(0, "<repo>/src")
from bibit_filesearch.bm25 import BM25Index
# 用同一份 chunks 文本灌进 BM25Index（与 retriever.warmup 同口径），然后：
hits = bm.search(query, top_k=1000)      # 拿原始分
```

**先看原始分跨度**：

- 跨度 < 3 倍 → 取好命中原始分的中位数即可。
- 跨度 ≥ 3 倍 → **用判据法**（中位数法在这种跨度下会把弱命中的文件压到无关文档之后）。

**判据法步骤**：

1. 挑 2~4 个"人工一眼能判对错"的查询（正确答案明确、且有一个明确的对照文件）。
2. 对每个候选 K，把每条判据写成"裕度"（正确答案分 − 对照分），算**相对裕度** = 裕度 / 较高分。
3. 选使 **min(所有判据的相对裕度) 最大**的 K。
4. 把每一步的数字与各候选取值都记到下表。

## 相关旋钮

```
search.bm25_weight      （0 = 关闭 BM25 路；默认 0.230769）
search.embed_weight     （默认 0.538462）
search.filename_weight  （默认 0.230769）
search.min_similarity   （默认 0.35，作用于**原始 cos**，不是 S_bm25）
search.bm25_half_score  （K，默认 2.8；0 = 退化为"命中即 1"）
```

`bm25_half_score = 0` 是合法的 debug 取值：`S_bm25` 变成指示函数（命中 1 / 未命中 0），
只在排查"某文件为什么没被召回"时用。

## 附：`min_similarity` 的尺度

门槛作用在**原始 cos** 上，而展示的是融合分，两者尺度不统一。被门槛剔掉的低 cos 文件
若同时没有关键词命中，就会整份消失（是"搜不到"而非"排错"）。更精确的判据是
「`S_sem` 低于阈值 **且** `S_bm25 = 0` **且** `S_name = 0`」——改它会连带改变结果集大小，
需单独一轮标定（见 [`design.md`](design.md) §5.2）。
